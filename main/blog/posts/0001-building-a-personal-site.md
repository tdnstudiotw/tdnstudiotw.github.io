# 從一個空資料夾開始設計自己的網站

一開始，我只是想做一個可以放文章的地方。後來才發現，真正困難的不是把頁面做出來，而是回答一個比較基本的問題：**我希望別人從這個網站帶走什麼？**

## 先決定它要成為什麼

這個網站不打算只服務單一主題。技術文章、地震與氣象觀察、專案開發紀錄，甚至一些沒有辦法立刻分類的個人筆記，都可以在這裡留下位置。

我希望它比較像一個入口，也像一張正在慢慢長大的地圖。訪客可以從首頁進入 Blog，也可以從專案卡片前往另一個獨立的工具或文件站。

> 好的網站不一定要一開始就很完整，但應該讓下一步有地方可以放。

## 為什麼先選 Markdown

Markdown 的好處是內容和介面可以分開。文章是純文字，能夠被 Git 追蹤，也不會被某一個後台系統綁住。之後即使換掉網站框架，文章仍然可以被重新處理。

目前的文章檔案會保留一小段 front matter，讓列表頁可以讀取標題、日期、分類與標籤：

```yaml
---
id: 0001
title: 從一個空資料夾開始設計自己的網站
date: 2026-08-17
category: 專案紀錄
tags: [網站, 設計, 專案紀錄]
---
```

這個格式也會成為之後本地編輯器的輸出格式。編輯器只需要協助填寫欄位與預覽內容，不需要改變文章本身的資料結構。

## 第一版想留下的功能

第一版先把最常使用的閱讀路徑做好：

- 從主網站進入 Blog。
- 用分類、標籤或關鍵字找到文章。
- 讀取 Markdown 並轉成適合閱讀的文章頁。
- 在文章之間前後瀏覽。
- 使用淺色或深色模式閱讀。

之後再加入圖片管理、文章草稿、編輯器與更完整的搜尋。先把可以長期維護的骨架做好，比一次把所有功能塞進去更重要。

## 接下來

這是一個起點，不是完成品。當第一篇文章真的被寫出來之後，網站的分類、元件與語氣都會逐漸變得更清楚。

我想保留這個過程，因為專案最後的樣子固然重要，但中間那些選擇也同樣值得被記下來。
